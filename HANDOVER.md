# Project Handover Document

## Overview

This is a custom Terraform provider (`gcxtras`) for managing Genesys Cloud Speech and Text Analytics (STA) resources. It's published under the namespace `gsyspslab/gcxtras` and is intended to complement the official `mypurecloud/genesyscloud` provider with STA-specific functionality that the official provider doesn't fully support.

## Resources and Data Sources

### Resources
- **`gcxtras_sta_program`** — Create/update/delete STA programs with topic associations and publishing
- **`gcxtras_sta_topic`** — Create/update/delete STA topics with phrases, dialect, participants

### Data Sources
- **`gcxtras_sta_program`** — Look up existing programs by name
- **`gcxtras_sta_topic`** — Look up existing topics by name + dialect (+ optional state filter)

## Key Technical Decisions and Lessons Learned

### Topic-to-Program Association (CRITICAL)

The Genesys Cloud API for associating topics with programs is non-obvious:

- **WRONG**: Sending `"topics": [{"id": "..."}]` in the program POST/PUT body — the API silently ignores this field
- **WRONG**: Sending `"programs": [{"id": "..."}]` in the topic PUT body — also silently ignored
- **WRONG**: Using `PUT /programs/{id}/mappings` with `topicIds` — this endpoint is for queue/flow mappings only (confirmed from SDK: `Programmappingsrequest` only has `QueueIds` and `FlowIds`)
- **CORRECT**: Sending `"topicIds": ["id1", "id2"]` (flat string array) in the program POST/PUT body

This was confirmed by reading the official Genesys Cloud Go SDK (`platform-client-sdk-go/v179`):
```go
type Programrequest struct {
    Name        *string   `json:"name,omitempty"`
    Description *string   `json:"description,omitempty"`
    TopicIds    *[]string `json:"topicIds,omitempty"`   // flat string array!
    Tags        *[]string `json:"tags,omitempty"`
}
```

### Strictness Type Mismatch

The API returns `strictness` as a JSON number but Terraform stores it as a string. The `TopicResponse` struct uses `json.Number` to handle this, and `.String()` is called when setting state.

### Topic Data Source Disambiguation

Multiple topics can share the same name across dialects. The data source requires both `name` and `dialect` to uniquely identify a topic. An optional `state` parameter (`latest` or `published`) further narrows the search.

### Publishing Programs

Publishing is done via `POST /api/v2/speechandtextanalytics/programs/publishjobs` with `{"programIds": ["..."]}`. A 2-second sleep is added after publishing to allow the job to complete before reading back state.

### Debug Logging

When `sdk_debug = true`, all API requests/responses are logged to `gcxtras_debug.log` in the working directory. This was essential for debugging the topic association issue. The log file is named differently from the official provider's debug to avoid conflicts.

## Release Process

1. Commit and push changes to `main`
2. Tag: `git tag v0.x.y && git push origin v0.x.y`
3. GitHub Actions workflow runs GoReleaser, builds multi-platform binaries, signs checksums with GPG, creates GitHub Release
4. Terraform Registry webhook picks up the release automatically

### Required GitHub Secrets
- `GPG_PRIVATE_KEY` — ASCII-armored GPG private key (no passphrase)

### GPG Key
- Generated locally, RSA 4096-bit, no passphrase
- Public key uploaded to both GitHub (account GPG keys) and Terraform Registry (signing keys)
- Export public key: `gpg --armor --export gsyspslab`
- Export private key (for secrets): `gpg --armor --export-secret-keys gsyspslab`

## Genesys Cloud API Reference

| Endpoint | Method | Purpose |
|----------|--------|---------|
| `/api/v2/speechandtextanalytics/programs` | POST | Create program (with `topicIds`) |
| `/api/v2/speechandtextanalytics/programs/{id}` | GET/PUT/DELETE | Read/update/delete program |
| `/api/v2/speechandtextanalytics/programs/publishjobs` | POST | Publish programs |
| `/api/v2/speechandtextanalytics/topics` | GET/POST | List/create topics |
| `/api/v2/speechandtextanalytics/topics/{id}` | GET/PUT/DELETE | Read/update/delete topic |

### Region Mapping
The provider maps AWS region identifiers to Genesys Cloud domains (e.g., `eu-west-1` → `mypurecloud.ie`). The full mapping is in `internal/client/client.go`.

## Known Limitations

- The program GET response returns `"topics": []` even when topics are associated — this is an API quirk. The provider sets `topic_ids` in state from what was configured, relying on `Computed: true` to avoid plan drift.
- Topic phrases are supported in the schema but haven't been extensively tested with the API.
- No import testing has been done yet.
